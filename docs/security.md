# Security & privacy — Onecarat Agent Office CC

## 1. What Office never does
- **It never calls a model.** No Anthropic API, Agent SDK, `claude -p`, prompt/agent-type hooks. All model calls, sign-in and billing stay in the official Claude Code, so Office adds **no extra cost**. The one model-visible footprint is the plugin skill's short description, which, like any skill, sits in each session's context (measured ~143 tokens before shortening; the shortened description is estimated at a few dozen). The hooks themselves add no model context.
- **It never reads, stores or forwards credentials.** It does not read `~/.claude/.credentials.json`, OAuth tokens, session cookies, API keys or `.env` files. The only file under the user's profile it writes is its own runtime file (below).
- **Claude Code configuration in the settings view (read-only).** On request from the page (token required, `GET /api/config`), the bridge reads Claude Code's documented configuration locations: managed policy, `~/.claude/settings.json`, `CLAUDE.md` files, `rules/`, `agents/`, `commands/`, `skills/`, `output-styles/`, `keybindings.json`, the project's auto-memory, the project's `.claude/settings*.json` and `.mcp.json` (`packages/event-bridge/src/config-scan.ts`). Files are read again on every request and nothing is kept. Before anything is sent: everything under a secret-looking key (`*key*`, `*token*`, `*secret*`, `*auth*`, `*credential*` …, whether a string, a list or an object) and **every** value under `env` / `headers` / `args` becomes `••• (hidden)`, URLs lose their query string (`?token=…` → `?***`), other strings go through the masking below, and from `~/.claude.json` **only** `mcpServers` and the current project's `allowedTools` / `mcpServers` / `enabled|disabledMcpjsonServers` / `hasTrustDialogAccepted` are taken (the account, `primaryApiKey`, usage records and other projects never leave the bridge). Folders are listed by file name plus front-matter `name`/`description`; Markdown is clipped to 64 KB. The `cwd` parameter must be an existing absolute folder, and only the fixed names above are read under it.
- **It never answers permission prompts and never types for you** (one exception: the Research Lab command, which Office pastes into the input box and never sends; section 1a). The built-in terminal runs the official interactive `claude`. Everything else that reaches it comes from the user's own keystrokes in the Office tab. Office never reads or parses its output, and never infers state from it. State still comes from hooks only. To know which session runs in the built-in terminal after "continue" or "pick a past session", the bridge gives that `claude` a random run id in its environment (`ONECARAT_OFFICE_TERMINAL`, a marker, not a secret); its hooks inherit it, the forwarder passes it on in a header, and the session named by a `SessionStart` with the current run id is the one followed. Office does not read the transcript files or the list of past conversations: the picker is Claude Code's own, drawn in the terminal.
- **It never sends data off the machine.** No telemetry, analytics or cloud sync.
- **It never edits `~/.claude/settings.json`.** The hooks come from the plugin and are removed with it.

## 1a. Research Lab: the two deliberate exceptions

Office mode keeps every rule above. Research Lab changes two of them, and only when the user presses **Start research**. A research runs in the user's own Claude Code session: the plugin ships a skill (`skills/research/SKILL.md`, the manager's procedure) and a subagent definition (`agents/researcher.md`). There is no second terminal and no second session.

**Exception 1: Office pastes one command line. Enter is the user's.** `Terminal.pasteLine` is the only code path through which Office writes to a terminal by itself; only the Research Lab controller calls it. **Office has no code that sends Enter**, and none that answers a prompt.
- Once per press: one bracketed paste of one line, `/onecarat-agent-office:research <findings> <researchers> <research id> <theme>`, into the input box of the Office terminal. Nothing is sent: the research starts only when the user presses Enter. A research that ends short, or whose end is not confirmed, is never pasted again; the user presses again.
- Every control character (C0, C1, DEL, Unicode line separators) is removed from the theme and from the whole line, so the text cannot act as a key press or end the paste early (and so smuggle in an Enter). Theme ≤ 500 characters.
- **Nothing is pasted** unless Claude Code is running in the Office terminal, a hook of that terminal's session has arrived (so it is past its start-up questions, such as the trust prompt), and no `PermissionRequest` is open in that session (pasted characters could act as key presses in a prompt). Otherwise the command is only shown on the page, for the user to copy. All of this is decided from hooks, never from terminal output.
- A command that was pasted and not yet sent blocks a second paste (it would land next to the first). "Drop it" on the page writes nothing to the terminal: the pasted text stays in the input box until the user clears it.
- A research the user starts by typing the command themselves (any terminal, IDE, Desktop app) is shown the same way; Office pastes nothing for it.
- **The plugin loosens no permission.** The skill has no `allowed-tools`, the researcher definition has no permission setting and no Agent tool (`tools: WebSearch, WebFetch, Write, Read`), and the skill tells the manager to run no shell command. Every permission prompt, the researchers' included, appears in Claude Code and is answered by the user there. `claude -p` and the Agent SDK are still not used. A test checks the shipped files for this.
- `~/.claude.json` is no longer read for the Research Lab (the earlier trust / MCP checks were removed with the code that pressed Enter).

**Permission waits that stay, and "Hide this wait".** When the user refuses a permission prompt, Claude Code sends no hook (measured on 2.1.323: no `Stop`, no `PermissionDenied`, no idle notice within three minutes). Office does not read terminal output, so it cannot know the prompt is gone; the wait stays on the page.
- The page shows who waits and for how long (the time the request arrived). Nothing is hidden or changed by itself as time passes: no state is made up.
- The user can hide a wait. That changes the display of that one agent and nothing else; it sends nothing to Claude Code. Office still has no code that answers a prompt.
- **Hiding is not evidence.** The request stays open inside the bridge until a hook closes it (the user's next prompt, that tool call ending, the end of the turn or of the session, for a subagent its next call or its end). Until then "Start research" still does not paste (pasted characters could land in a prompt that is in fact still open): the command is shown for the user to copy and paste themselves, and the page says that Office cannot know how the request ended. The automatic return to the Research Lab is held back the same way.

**`check` runs `claude --version`.** This is the only place where Office's own code runs `claude` (the built-in terminal starts the user's interactive `claude` on request; that is the user's session). Only the `check` command does it, never `start` / `stop` / `status` / `open`, and never the bridge.
- The file is the absolute path the built-in terminal would start; it is run without a shell (a `.cmd` / `.bat` on Windows is therefore not run at all), with the argument `--version` and nothing else, stdin closed, stderr dropped, a 5 second timeout and a 64 KB output limit, and with the session markers removed from its environment.
- From the output only the first `N.N.N` is read, to say whether the Research Lab was checked on that version, is untested on it, or cannot work with it. No session is started and no model is called.
**Exception 2: research results are on disk.** Claude Code writes them (through its normal permission prompts) to `<working folder>/research/<research id>/`; **Office never writes, changes or deletes them.** They remain after Office stops.
- **Which folder is read (changed in the two-view version).** The working folder is the one of **the session that runs the research**, taken from the `cwd` its hooks report (before: only the folder Office was started in). A written file is read only when **all** of this holds: the hook's `cwd` is a local absolute path (a UNC path `\\host\share` is refused, so reading never makes this computer contact another machine); the file path of that `PostToolUse(Write)` hook is exactly `<that cwd>/research/<id>/<file>`, with an id of the form `r-YYYYMMDD-HHMMSS-xxxx` and a `.json` file directly inside; both folders are real folders, not links. A hook can only come from a local Claude Code that holds the access key (section 4), and what is read is still limited to that one folder shape.
- **Restore after a restart is narrower:** earlier researches are read back only from the folder Office was started in and from the folder currently chosen in the built-in terminal. A research of any other folder is shown while Office follows it live and is **not** restored later (its files stay where they are).
- Office reads only regular `.json` files directly in such a folder. Links are not followed at any level (`lstat`), sub-folders are not entered, a file is at most 256 KB, a research at most 60 result files and 60 reviews; at most 20 earlier researches are listed.
- The content is untrusted (it was put together from web pages). Every field is type-checked, clipped and copied into a new object; a file naming another research id, a result without a title, or a review whose verdict is not one of the two words is reported and skipped. `engine`, and who wrote a card (`agent_id` of the Write hook), are set by the bridge, never taken from the file or its name. Nothing in a file is executed.
- The page shows card text as plain text (never as HTML) and makes a source a link only when it parses as an `http:` / `https:` URL (`rel="noopener noreferrer"`).
- A new card is read when the `PostToolUse(Write)` hook for that file arrives (the write has finished); the folder is read once more when the manager's turn ends and when `summary.json` is written.
- **No completion without evidence.** A researcher is "completed" only on Claude Code's own completion notice (`task-notification`, status completed), or after its report reached the manager and the manager's next `Stop` no longer lists it as running; a `SubagentStop` alone is never an end. A research is "completed" only when `summary.json` exists; otherwise it is shown as "end not confirmed". No progress percentage is shown.
- The skill and the researcher definition tell the model to treat web content as data, to list only sources it opened, and not to invent findings or URLs. That is an instruction to the model, not a guarantee: the card's caveats and sources are what the model wrote.

**"Open folder" in the Console** (also in Office mode; the one addition to it). `POST /api/reveal` asks the system file manager to show a file Claude Code wrote.
- **The page never has the path.** When a `PostToolUse(Write)` hook arrives, the bridge keeps the full path in its own memory and replaces it in the event by a display name (the last two parts, as before) and an id (`HMAC(token, path)`, 24 hex). The page sends that id; a path, or an unknown id, is refused. So the page cannot make the file manager open anything but a file the bridge recorded. Files whose names look sensitive (`.env`, keys) are never recorded.
- **Nothing is opened or run.** Only if the recorded path is a regular file right now (`lstat`; a link does not count) is it selected in its folder: Windows `<SystemRoot>\explorer.exe /select,"<path>"` (absolute program path, no shell), macOS `/usr/bin/open -R <path>`, Linux `xdg-open <parent folder>`, with `xdg-open` resolved to an absolute path from the absolute PATH entries (never the working folder; if it is not found, nothing is started). If it is anything else by now (gone, replaced by a folder such as an `.app` bundle, a link, a special file), the recorded path is not touched and only its parent folder is shown; without a parent folder nothing happens.
- Not verified against the real file managers: a path with a comma on Windows.

## 2. The main protection is that nothing is kept (masking only helps)
Prompts, final replies, command snippets and **terminal output** are shown on screen. **They are held in memory only** and are **never written to disk** by Office. The terminal scrollback lives in the bridge (bounded, 512 KB) so that a reloaded tab can redraw. It is not put in `localStorage` or `sessionStorage`. Everything disappears when Office stops, or when the user clears the history in the UI (which also clears the terminal scrollback).

Display masking hides some secret-looking strings in the office view: `KEY=…` / `token: …` / `X-API-Key: …` (any name containing key, token, secret, password, auth…, including bare keywords, header names and `--flag=` forms), `--token value` flags, `Bearer …`, `user:pw@` in URLs, known key prefixes (`sk-`, `ghp_`, `AKIA` …), and long runs that mix letters and digits. It also hides the names of `.env`, credential and key files. **Masking is a best-effort extra, not a guarantee.** Short tokens, tokens split by separators, or secrets typed in plain words can pass through. **The terminal is not masked at all**: it shows exactly what `claude` prints, like any terminal. If a prompt contains a secret, assume it is visible on your own screen while Office runs. It is still not saved and not sent anywhere.

## 3. Data minimization at the source
The hook forwarder (`plugin/onecarat-agent-office/scripts/forward-lib.mjs`) keeps only the fields Office displays and clips them, all **before** anything leaves the hook process:
- kept: event name, session/agent ids and type, cwd, prompt (≤4000 chars), final reply (≤4000), tool name, tool_use_id, duration, error line (≤600), notification type, and from `tool_input` only `file_path/path/pattern/command/url/query/description/subagent_type/message`
- **in the bridge only:** the full path of a file written with `Write`. Events, and so the page, get its last two parts and an id (section 1a, "Open folder")
- **read by the bridge, on purpose:** Research Lab result files, `research/<research id>/*.json` in the working folder of the session that runs the research (section 1a). They are not hook data; their checked content is shown as cards
- **added for the Research Lab (completion only):** on `Stop`, the list of background tasks reduced to `id`, `status` and `agent_type` per task (at most 50). Their description, output file and everything else in that list are dropped. It is how Office learns that a background subagent has really ended
- **dropped:** file contents (`content`, `old_string`, `new_string`, edits…), tool outputs (`tool_response`, except the Agent tool's `agentId`/`isAsync`), `transcript_path`, everything else

## 4. One key is the only way in
Each launch creates one random token (48 hex; the README calls it the *access key*). It is required for every way into Office's data or controls: hook intake, the event stream, the terminal, clear and shutdown.

| Control | How |
|---|---|
| Bind | `127.0.0.1` only (port 47821 by default) |
| Hook intake `/hook` | token header, compared in constant time. **Requests with browser markers (`Origin`, `Sec-Fetch-*`) are refused** (CSRF). JSON only, 512 KB limit, answered before processing |
| Event stream `/events`, `/api/config`, `/api/clear`, `/api/shutdown`, `/api/reveal`, `/api/research`, `/api/research/start`, `/api/research/dismiss`, `/api/waits/dismiss` | token header required (401 without). Cross-site requests refused (`Sec-Fetch-Site` / `Origin`) |
| `/api/reveal` | takes a file id only (never a path); shows the file's folder, runs nothing (section 1a) |
| `/api/research/start` | the only request that makes Office write into a terminal: one pasted command line, never Enter, under the conditions of section 1a. Theme ≤ 500 characters without control characters, count 1–20, researchers 1–3 |
| `/api/research/dismiss` | drops a research that has not started; writes nothing to the terminal and stops nothing |
| `/api/waits/dismiss` | "Hide this wait": removes one agent's permission wait from what the page shows (body: a session id and, for a subagent, its agent id; both must be known strings). It adds one in-memory event and nothing else: nothing is written to a terminal, no prompt is answered, and the agent is recorded neither as allowed nor as refused |
| Terminal WebSocket `/pty` | checked **before the WebSocket exists**: `Host` allowed, `Origin` exactly `http://127.0.0.1:<port>`, and the token, offered as a WebSocket subprotocol `office-token.<token>` (browsers cannot set WebSocket headers). The server answers only `office.v1`, so the token is not echoed back. 64 KB message limit |
| `/api/health` | without the token it answers only "this is Office" (name, version, `authed:false`). No events, no counts, no terminal state. A caller that sends a random nonce (`x-office-nonce`) also gets `HMAC-SHA256(token, nonce)` back: proof that the answer comes from the process holding the token, without revealing it |
| Stale runtime file | a runtime file can outlive its bridge (crash, forced kill, power loss), and something else may listen on that port later. **The hook forwarder sends nothing until the listener has proved it holds the token** (the nonce check above); before that it does not even connect if the recorded process is gone or the file is older than the last boot. The launcher and the bridge use the same proof before they call something "running" |
| How the page gets the key | the launcher opens `http://127.0.0.1:<port>/#t=<token>` **directly in the browser**. Browsers never send the URL fragment to a server, so the key is in no request line or access log. The page moves it out of the address bar at once (`history.replaceState`) and keeps it for that tab only (`sessionStorage`). On Windows the browser is opened through the URL protocol handler, because `explorer.exe` drops the fragment (measured); `rundll32.exe` is started **by absolute path** from the Windows folder (a bare name would be looked up in the working folder first, so a `rundll32.exe` planted in a cloned repository would run and receive the keyed URL). On macOS / Linux, where every local user can read the arguments of a process (`ps`), **the keyed URL is never put on a command line**: the launcher writes a private hand-off page (mode 0600, random name, removed after 20 seconds; macOS: in the runtime folder, Linux: in the home folder because sandboxed browsers cannot read hidden folders), asks the browser to open that file, and the file sends the tab on to Office |
| Never printed | the launcher and the bridge **never print the token**. The skill runs the launcher, and its output becomes part of the Claude Code transcript. A page opened by hand without the key shows "no access key" and no data |
| What the terminal can run | only `claude`, with arguments fixed by the bridge: `--session-id <uuid>` (new conversation), `--continue` (the folder's most recent one) or `--resume` (Claude Code's own picker of past conversations, shown in the terminal). The UI cannot pass a program, arguments or environment. It can only pick one of those three by name (anything else starts nothing) and the folder, which must be an absolute local path (relative and `\\host\share` paths are refused, also for the configuration view). **`claude` is resolved once from PATH to an absolute path and never looked up in the working folder** (cmd.exe would otherwise run a `claude.cmd` planted in a cloned repository, before Claude Code's own trust prompt); if no `claude` is on PATH the terminal is unavailable. A `.cmd` shim is run through `cmd.exe` by absolute path. The calling session's private variables (`CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_MESSAGING_*`, `CLAUDECODE` …) are removed, `NoDefaultCurrentDirectoryInExePath=1` is set for the shells `claude` starts, and the user's own configuration (`CLAUDE_CONFIG_DIR`, provider settings) is kept |
| What the launcher accepts | `--port N` (1024–65535), `--cwd DIR` (must exist), `--no-terminal`, `--no-open`; anything else is refused. The plugin skill pre-approves the launcher, so this allow-list is what a prompt-injected instruction could reach. The bridge's development flags (serve another folder as the UI, open another page with the key, allow another origin) are ignored by the shipped bundle and, from source, accept loopback URLs only |
| DNS rebinding | `Host` must be `127.0.0.1:<port>`, `localhost:<port>` or `[::1]:<port>` (else 421) |
| Page | CSP `default-src 'self'` (no remote scripts), `connect-src 'self'`, `frame-ancestors 'none'`, `nosniff`, `no-referrer` |
| Runtime file | `%LOCALAPPDATA%\onecarat-agent-office\bridge.json` (macOS: `~/Library/Application Support/…`, Linux: `$XDG_STATE_HOME/…`) holding port + token, removed on stop. On macOS/Linux the folder is 0700 and the file 0600; on Windows file modes have no effect and the protection is the user-only ACL of `%LOCALAPPDATA%` |
| Browser history | the page removes `#t=…` from the address bar at once, but a browser may still have recorded the first URL in its history. That key is useless as soon as Office stops (a new one is made per launch) |

**Read this:** with the built-in terminal, **the token is a remote-control key for Claude Code on this computer.** Anyone who has it can type into the `claude` running in Office, and that `claude` can run commands with your permissions (subject to its own permission prompts and mode). Even on the same PC, a leaked token is a way in. Do not paste the tokened URL anywhere. Stopping Office makes the token useless (a new one is made at each launch).

**Accepted limit:** any process running as the **same OS user** can read the runtime file. With the token it can post events, read the view, and type into the built-in terminal. Office does not defend against your own account's processes. That account can already run `claude` and read your files and transcripts. Office does defend against other users, web pages and other machines.

## 5. Failure behavior (Claude Code is never blocked)
- Hooks are `async: true` command hooks: Claude Code does not wait for them (measured: sync waited 2125 ms for a 2 s hook; async did not wait).
- The forwarder always exits 0 with no output. If Office is not running it does not even open a connection, so no hook errors appear.
- `onFailure: "block"` is never used.
- A malformed request (bad %-escapes, odd paths) is answered with 400, never with a crash; a malformed terminal message is ignored.
- The masking patterns have bounded repetition and run in linear time: a crafted `CLAUDE.md` or prompt (`key-key-key-…`) cannot stall the bridge. The configuration view reads regular files only. `office stop` signals a process only after it answered as Office, so a stale runtime file whose pid was reused never gets an unrelated process killed.
- If the built-in terminal cannot be used (no node-pty binary for this OS/CPU, e.g. Linux today), **Office starts read-only** and says why. Hooks, the office view and the event stream are unaffected.
- Stopping Office ends a `claude` running in the built-in terminal (it is killed, so its `SessionEnd` hook may not fire).

## 6. Supply chain
- `dist/bridge.mjs`, `dist/office.mjs` and `dist/ui/` are bundled from this repository's `packages/` with esbuild/Vite. Bundled third-party code: `ws` (bridge), React and xterm.js (UI). **CI rebuilds them and fails if they differ from the committed files**, and the build fails if the bundled bridge does not start.
- `dist/vendor/node-pty/` is **not built by us**. It is the published `node-pty@1.1.0` package (Microsoft, MIT, N-API prebuilds for win32-x64/arm64 and darwin-x64/arm64, debug symbols left out). **CI fetches the npm tarball, checks its sha512 against the pinned integrity, and fails unless every vendored file is byte-identical** (`scripts/vendor-node-pty.mjs --check`). No other native module may appear in `dist/` (the build fails).
- No CDN or remote assets at run time.

Please report security issues privately: on GitHub, open this repository's **Security** tab and choose **Report a vulnerability** (private vulnerability reporting). Please do not open a public issue for a security problem. See also [SECURITY.md](../SECURITY.md).
