# 依存している Hook イベントの一覧

Onecarat Agent Office が Claude Code から受け取る情報は、ここに書いた Hook イベントだけです。Claude Code の仕様が変わって表示がおかしくなったときは、この表を見て直す場所を探してください。

- 確認した資料: Claude Code 公式の Hooks リファレンス（英語） https://code.claude.com/docs/en/hooks
- 確認した日: 2026-11-21
- 公式資料には 33 種類のイベントが載っています。このうち使うのは下の 11 種類だけです。それ以外のイベントは登録していないので、届きません。

## 1. イベントごとの使い道

| Hook イベント | 読む項目 | 小窓での使い道 | 届かなくなったとき |
|---|---|---|---|
| `SessionStart` | `cwd`、`source` | セッションの始まり。フォルダ名の表示 | 窓は次のイベントで開く。困らない |
| `SessionEnd` | `reason` | お別れの動きをして、窓を閉じる | 窓が自動では閉じなくなる（手で閉じられる） |
| `UserPromptSubmit` | `prompt`（利用者が書いた依頼文は送らない。Claude Code 自身が始めた番のときだけ、先頭のタグを送る） | マネージャーが「考え中」になる。先頭のタグで、利用者の依頼か、Claude Code 自身が始めた番かを見分ける | マネージャーが考え始める瞬間がわからない |
| `PreToolUse` | `tool_name`、`tool_use_id`、`agent_id`、`agent_type`、`tool_input` からは「テストを動かすコマンドかどうか」とサブエージェントの種類だけ | 道具を使い始めた。「調査中」「編集中」「実行中」などの動き。`Agent` ツールならサブエージェントへの指示 | 棒人間が作業の動きをしなくなる |
| `PostToolUse` | `tool_name`、`tool_use_id`、`duration_ms`、（`Agent` ツールのときだけ）`tool_response.agentId` / `isAsync` | 道具が終わった。承認待ちの解除。サブエージェントの結果を受け取った合図 | 承認待ちの表示が消えるのが遅れる |
| `PostToolUseFailure` | `tool_name`、`is_interrupt`（エラーの文は送らない） | 失敗して「やり直し中」、中断 | 困った顔にならない |
| `PermissionRequest` | `tool_name`、`agent_id` | **承認待ちの表示**（主な手がかり） | 承認待ちがわからなくなる（下の `Notification` が代わりになるが、6 秒ほど遅れる） |
| `Notification` | `notification_type` | `permission_prompt`: 承認待ちの予備の手がかり。`idle_prompt`: マネージャーを待機に戻す。この 2 種類だけ登録している | 予備がなくなるだけ |
| `SubagentStart` | `agent_id`、`agent_type` | サブエージェントの棒人間が現れる | サブエージェントは、自分の道具のイベントが届いた時点で現れる |
| `SubagentStop` | `agent_id`、`agent_type`、`last_assistant_message`（あったかどうかだけ） | サブエージェントが報告して帰る | サブエージェントが机に残り続ける |
| `Stop` | `last_assistant_message`（あったかどうかだけ）、`background_tasks`（id・状態・種類だけ） | マネージャーの番が終わり、待機に戻る。終わりの合図が来なかったサブエージェントの片づけ | マネージャーが作業中のままに見える |

すべてのイベントで共通して読む項目: `hook_event_name`、`session_id`（どの窓に出すか）、`cwd`（フォルダ名）、`agent_id` / `agent_type`（サブエージェントの中で起きたイベントかどうか）、`permission_mode`（受け取るが、小窓では表示しない）。

## 2. 承認待ちをどう知るか

公式資料で確認した内容です。

- `PermissionRequest` は「Claude Code が道具を使う許可を利用者に尋ねようとするとき」に起きます。尋ねる画面が出るときだけ起き、サブエージェントの中でも起きます。小窓の承認待ちは、主にこれで出します。
- `Notification` の `permission_prompt` は、尋ねる画面が出てから約 6 秒待たされたあとに起きます。どのエージェントが待っているかは書かれていません。そこで、`PermissionRequest` が一度でも届いたセッションでは使わず、届かない場合の予備にだけ使います。
- **利用者が「拒否」を選んだことを知らせるイベントはありません。** `PermissionDenied` というイベントはありますが、これは自動モードが拒否したときだけで、利用者が画面で拒否したときには起きません。そのため小窓は、次のどれかが起きた時点で承認待ちの表示を消します。
  - その道具が終わった（`PostToolUse` / `PostToolUseFailure`）
  - 同じエージェントが、3 秒以上あとに別の道具を使い始めた（`PreToolUse`）
  - マネージャーの番が終わった（`Stop`）、利用者が次の依頼を出した（`UserPromptSubmit`）
  - サブエージェントが終わった（`SubagentStop`）、セッションが終わった（`SessionEnd`）
  - マネージャーに `idle_prompt` の通知が届いた（Claude が応答を終えてから約 60 秒、入力がないとき）
- このため、拒否したあとも表示が残ります。残る長さは、拒否のしかたで変わります。
  - 拒否したあと Claude が作業を続けた場合: 次の道具を使い始めるか、番が終わるまで（ふつうは数秒）。
  - **拒否と同時に番が中断された場合: 利用者が次の依頼を送るまで残ります。** 中断された番では `Stop` が起きず（公式資料に明記）、拒否された道具には `PostToolUse` も `PostToolUseFailure` も起きないためです。
- 拒否や中断を知らせるイベントや項目は、公式資料にありません（2026-11-21 に確認）。`PostToolUseFailure` の `is_interrupt` は、拒否ではそのイベント自体が起きないので使えません。`idle_prompt` が中断のあとに届くかどうかは、公式資料に書かれていません。実機で確かめたところ（2026-11-21）、拒否して中断したあとも表示は消えませんでした。中断のあとには届かないものとして扱います。
## 2.1 表示の言語

イベントとは関係なく、表示の言語は Windows の表示言語で決めます（日本語なら日本語、それ以外は英語）。設定はありません。文言は `packages/domain/src/i18n.ts` の 1 か所にあります。

- 窓とタイトルバー: 窓の部品（WebView2）が知らせる言語（`navigator.language`）を使います。タイトルバーの「承認待ち」は、窓が自分の言語の文言をアプリに渡します。
- 起動スクリプト: レジストリの表示言語（利用者の選択、なければ PC の設定）を読みます。読めなければ、地域の形式で決めます（`packages/launcher/src/lang.ts`）。

## 3. 壊れにくくするための決まり

- **知らないイベントは無視します。** 登録していないイベントは届きません。届いたとしても、名前を知らないイベントは何もせずに捨てます。
- **知らない項目は捨てます。** 転送スクリプトは、上の表にある項目だけを取り出して送ります。それ以外（会話ファイルの場所、道具の出力、ファイルの中身など）は、送る前に捨てます。
- **文章は送りません。** 小窓は絵だけを描くので、絵に必要な判断は転送スクリプトの中で済ませ、結果だけを送ります。コマンドは「テストを動かすものかどうか」だけ、依頼文は「Claude Code 自身が始めた番なら、その先頭のタグ（どのサブエージェントの報告か、タスクがどう終わったか）」だけです。利用者が書いた依頼文、コマンド、ファイルの名前、URL、検索の語句、エラーの文は送りません。サブエージェントの報告の本文も送りません。判断の決まりは転送スクリプトと変換の 2 か所にあり、同じであることを自動テストで確かめています。
- **形の違うデータでも落ちません。** 文字列のはずの項目が数や配列でも、その項目を「なし」として扱います。JSON として読めないものは受け取って捨てます。
- **Hook は Claude Code を止めません。** すべて `async: true`（裏で動かす）で登録しています。公式資料によると、裏で動く Hook は結果を待たれず、許可や拒否の判断にも影響しません。転送スクリプトは、何が起きても何も表示せず、終了コード 0 で終わります。小窓アプリが動いていないときは、通信もしません。

## 4. 直す場所

| 変わったこと | 直すファイル |
|---|---|
| イベントの名前や、登録のしかた | `plugin/onecarat-agent-office/hooks/hooks.json` |
| 送る項目（増やす・減らす） | `plugin/onecarat-agent-office/scripts/forward-lib.mjs` の `pickHookFields` |
| イベントの項目名や意味 | `packages/adapter-claude-code/src/normalize.ts` |
| 状態の決めかた（承認待ちをいつ消すか、など） | `packages/domain/src/reducer.ts` |
| 状態から棒人間の表情・しぐさへの対応 | `packages/domain/src/expression.ts` |
| 上の動作を確かめる自動テスト | `packages/adapter-claude-code/test/pipeline.test.ts`、`packages/office-ui/test/scene.test.ts` |

小窓アプリ本体（Rust）が読むのは、`session_id`（どの窓か）、`cwd`（同じフォルダかどうか）、イベント名が `SessionEnd` かどうか、の 3 つだけです（`src-tauri/src/router.rs`）。
